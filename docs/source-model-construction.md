# Independent source-model construction

The `surface-model` contract (manifest 1.7) carries author-defined surface geometry without an image volume. Native coordinates are `SOURCE_XYZ` in millimeters. No anatomical axis assignment, RAS conversion, MRI registration or correspondence with another dataset is implied. The common source acquisition, build, library, validation and serving interfaces apply to this representation.

## First source: Z-Anatomy

The pinned upstream source is commit `9de5d6912a1b0df9cab739d57f00e036b0496ddc`. The local original `Startup.blend` has SHA-256 `9f08a17ea0115fed80b2a73ecdf0a1bc2ab2f6956f37c593ce23d513ea35afcd`. The source license and complete upstream README attribution are included in each local package. They retain the original source credits; the project does not invent a per-object authorship assignment. The local data and all derived models remain separate from software distributions.

The current recipe selects 286 original objects, including the [73-object nuclear, limbic, brainstem and sellar expansion](detailed-anatomy-and-variation.md). Revision 4 supplied 119 objects; later increments add [38 cerebellar and ventricular objects](z-cerebellar-ventricular-context.md) and [56 cortical surface objects](z-cortical-surface-anatomy.md). The initial 94 objects covered 34 arterial models, 17 venous models, 28 cranial-nerve/root models, six skull bones, three dural sheets and six brainstem context models. The additional 25 objects provide bilateral pericallosal, callosomarginal, frontal callosomarginal branches and ophthalmic arteries; cochlear and vestibular nerve components; optic chiasm, optic tract and lateral geniculate components; cochlea and vestibule models; corpus callosum and cingulate context. These are source entries rather than a count of complete or unique anatomical structures. The unsuffixed cochlear nerve retains unspecified laterality. Original two-point foramen and canal labels remain separate from surface geometry. Nine author-indicated endpoints are available through the [source-annotation teaching workflow](source-annotation-teaching.md). CN courses retain their supplied extents without a new cisternal/canalicular/extracranial partition. Dural sheets do not define arachnoid membranes or cisternal boundaries.

Three additional curricula, `z-anatomy-distal-arteries`, `z-anatomy-visual-auditory-pathways` and `z-anatomy-petrous-neuroanatomy`, contain 28 context/detail views. Their presets fit the complete visible source components. The source objects remain educational models in independent native XYZ coordinates. The source's vestibule model includes attached semicircular components; its original name and extent are preserved.

The initial base-stage package retains original mesh vertices and polygons. Blender triangulates these polygons without adding vertices. Curve objects retain their author-defined control points, handles, radius, bevel and resolution; the pinned Blender runtime converts the supplied curve definition. No project subdivision, smoothing or new sampling resolution is added. Original mesh modifiers are recorded but not evaluated in this initial representation. A base object may therefore omit an authored modifier effect: the anterior communicating artery has a mirror modifier, the ethmoid has Boolean cell modifiers, and some nerve roots, venous and dural objects have subdivision or solidification modifiers. This representation must not be described as a complete evaluated rendering of those authored objects. Recipe revision 2 adds the explicit `author-viewport` stage. It evaluates the original viewport modifier stack using the pinned Blender dependency graph without changing any modifier settings. Both base vertices/polygon loops and the resulting vertices/triangles are retained. This includes the author-defined mirror, Boolean, subdivision and solidification effects; they remain conceptual source-model operations, not observed anatomical detail. The 23 mesh objects and 71 original curve objects in package `d6eb1a83d8d930cd` passed independent comparison against the original Blender file. No project-created symmetry or refinement is added.

## Units and construction

Use the independent `NeuroImage` Conda environment for project code. Blender `5.2.2 LTS` is a separately recorded application runtime with its own embedded Python; it is not a replacement project environment. Install the declared Blender version using its official application distribution and keep the executable on the local path. Construction checks the exact version string.

```bash
conda run -n NeuroImage python -m neuroimage acquire z_anatomy --data-root /path/to/imaging-data
conda run -n NeuroImage python -m neuroimage build z_anatomy --data-root /path/to/imaging-data --workers 2
conda run -n NeuroImage python -m neuroimage validate /path/to/imaging-data/derivatives/z_anatomy/VERSION/manifest.json
```

Acquisition uses source hashes and reuses existing files. The recipe reserves a 3 GiB additional construction peak plus the configured HDD safety floor. Blender runs with factory settings, automatic embedded scripts disabled and bounded worker threads. The original source declares metric units with scale length 1.0. Original object coordinates and world matrices are retained; the explicit metric transform multiplies world meters by 1000. A few source matrix last rows differ from affine `[0, 0, 0, 1]` by approximately `6e-8`; only this numerical homogeneous row is canonicalized. The original matrix and discrepancy remain in provenance. Blender's own three-component affine multiplication independently checks the transformation.

## Recovery and acceptance

Source geometry caches are keyed by source hashes, extraction implementation, runtime and declared scale. Completed extraction objects survive interruption. The package checkpoint records individual assets and hashes; repeat the same command to resume. Immutable hard links are preferred where supported. On filesystems returning `EPERM`, `EXDEV` or `EOPNOTSUPP`, necessary copies produce a self-contained portable atlas; the original cache and acquired source remain untouched.

The first package `ce8b178f36fea7be` passed fresh checks of all 286 asset hashes and geometry relationships. Original-runtime comparison checked every source vertex and triangle across all 94 objects. The maximum difference between independently evaluated Blender affine multiplication and retained float64 transformation was `0.0000745024 mm`, within expected floating-point rounding. No-op resume reused all 286 assets without recomputing geometry. These are engineering checks, not anatomical or instructor acceptance.

`tests/test_model_geometry.py` rejects changed positions, topology, source identity, native targets and invented anatomical coordinate assignments. `scripts/verify_z_anatomy_source.py` runs in Blender with auto-execution disabled to compare the package against the original source. The initial verification script incorrectly interpreted Blender's `autoexec_fail` flag, which indicates that a source script was blocked. The corrected verification checks that script auto-execution is disabled; source scripts remained blocked in both runs.

Earlier diagnostic failures included a strict affine-row check and unsupported hard links on the data filesystem. Their concise receipts are retained with this session. The original data and completed extraction cache were preserved; no failed geometry is silently accepted.

Revision 4 package `dec8e85dcd4597f1` passed all 119 original-source geometry comparisons and unchanged reconstruction. All 28 new browser views, three scene restore/import cases and ten credited teaching archives passed acceptance. The maximum independent Blender transformation difference remains below 0.000075 mm. The exact receipts are indexed in `config/z-anatomy-fine-content-verification-2026-10-14.json`. Instructor case ZPN-20261014-01 is recorded separately in `config/instructor-review-petrous-context-2026-10-14.json`.
