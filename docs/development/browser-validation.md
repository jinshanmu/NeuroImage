The explicit canonical TCK reader retains every line boundary, and the trajectory draw pass applies actual per-bundle state and physical slab matrices. Fixed colors disable its default directional coloring and random dither. A truthy negative minimum length avoids the renderer's zero-value early return without dropping any source trajectory.

## Surface opacity (2026-10-24)

The pinned native mesh renderer mixed opaque and transparent surfaces in loading order. An opaque surface drawn later could overwrite a translucent foreground because translucent fragments do not write depth. It also applied the RGB alpha blend factors to framebuffer alpha, reducing alpha over an already opaque background and allowing the page compositor to influence the result.

The shared normal 3D surface path establishes opaque depth before compositing transparent source surfaces. It preserves the source's front-face orientation, lighting and clipping predicate. No cap, fill, smoothing, voxel or triangle changes are made. A read-only audit of all 62 current CerebrA cortical meshes found 667,330 vertices and 1,332,988 triangles, with no boundary, nonmanifold or inconsistent-winding edges and no degenerate triangles.

`surfaceTransparency.test.ts` uses deterministic depth, culling and blend calculations to verify foreground/background composition, camera-dependent order, effective opacity, two-face drawing, opaque-background alpha and GL-state restoration. `cutawayRenderer.test.ts` checks the actual shared pipeline, cutaway programs, normal correction, zero-opacity filtering, native 2D/opaque fallback, synchronous depth picking, failures and shader cleanup. Normal transparency uses bounds-based mesh sorting; intersecting or self-overlapping transparent meshes can still have per-fragment ordering limitations. It does not claim order-independent transparency. Browser visual or frame-rate checks were not run for this change.

The initial opacity correction introduced a performance regression: 62 translucent meshes repeated 12 GL state queries and 3 capability queries each, submitted the complete geometry twice, and uploaded identical camera matrices per mesh. A first performance revision replaced this with one shared GL scope and one two-sided draw per mesh. That revision reduced driver queries but allowed far or back-facing triangles to overwrite the near surface, so it is superseded by the depth-compositing correction below. Batch-level state capture and per-program camera uniform reuse remain in place.

Opacity range controls use `FrameRange`/`FrameValue` to show the native thumb immediately and submit only the latest value per animation frame. Release, keyboard completion and blur flush the final value; disable, external changes and unmount cancel stale work. Selected-object controls are keyed by source structure so a queued opacity cannot target a newly selected object. Scheduler tests cover rapid inputs, skipped React acknowledgements, reset/blur and cancellation. These counters and scheduling checks do not measure actual browser frame rate.

## Opacity continuity and framing (2026-10-25)

The opaque-to-transparent transition previously changed both face culling and depth writes. Unsorted triangles could then overwrite the visible front surface, even at 0.95 opacity; sorting object centers cannot fix triangle order inside a cortical mesh. Automatic framing also excluded zero-opacity structures, causing a second jump at the slider endpoint. Framing now depends on explicitly displayed structures and enabled context, independent of their opacity.

`SurfaceOIT` copies existing opaque depth, finds the nearest source surface per pixel, then accumulates its exact color/alpha separately from order-independent weighted deeper layers. The resolve converges to the opaque near-surface result as alpha approaches one. This requires two batched geometry passes and a screen resolve, with cached viewport-sized targets and shader programs, no CPU triangle sorting or image readback, and a constant number of GL state queries. Half-float render targets use the [WebGL floating-point color-buffer extension](https://registry.khronos.org/webgl/extensions/EXT_color_buffer_float/). If unavailable, the single-pass fallback retains native front-face culling and nearest depth, rather than allowing rear triangles to overwrite the foreground. Deeper layers remain a weighted approximation; the exact nearest layer removes the previous opaque-endpoint discontinuity.

`scripts/check_surface_oit.py` compiles the actual exported GLSL and the pinned NiiVue Phong/vertex programs in a standalone software Mesa EGL/GLES context. It checks 0.95/0.99/1 opacity, six triangle orders, zero opacity, opaque occlusion, cutaway, nonbinary depths, nonzero viewport origins, and single-sample/4x-MSAA default-framebuffer depth copies. This real raster test found and corrected a low-precision depth-sampler defect; depth samplers are explicitly high precision. Pixel tolerances are two 8-bit channel levels, with one-level tolerance for order invariance. The unit test does not launch a browser or access a webpage, and does not measure interactive browser FPS.
